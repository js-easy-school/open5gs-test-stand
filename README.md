# Тестовый стенд 5G-ядра: Open5GS + UERANSIM в Docker

Стенд для функционального тестирования ядра мобильной сети 5G SA: своя сборка образов,
развёртывание одной командой, автотесты на pytest и готовый CI-пайплайн.

Проект собран под конкретную задачу QA: **проверить, что абонент регистрируется в сети,
получает сессию передачи данных, а посторонний — не получает ничего**.

## Что внутри

```
абонент (UERANSIM UE)
   └─ базовая станция (UERANSIM gNB)
        └─ AMF ── AUSF ── UDM ── UDR ── MongoDB
             ├─ SMF ── PCF ── BSF
             ├─ NSSF
             └─ UPF ── интернет (пул 10.45.0.0/16)
   всё через NRF (реестр функций) и SCP (прокси сигнализации)
```

| Файл | Назначение |
|---|---|
| `docker/Dockerfile.open5gs` | свой образ ядра: Ubuntu 22.04 + Open5GS из PPA, один образ на все NF |
| `docker/Dockerfile.ueransim` | свой образ радиосети: сборка UERANSIM из исходников, многоступенчатая |
| `docker/Dockerfile.tests` | образ прогона тестов, тот же локально и в CI |
| `docker/entrypoint.sh` | ожидание зависимостей и подъём туннеля для UPF |
| `docker-compose.yml` | тестовая схема: 14 контейнеров, статические адреса |
| `config/*.yaml` | конфигурации всех сетевых функций и радиочасти |
| `tests/` | автотесты: инфраструктура, база абонентов, регистрация, негативные сценарии |
| `docs/test-plan.md` | тест-план с трассировкой требований на тесты |
| `.gitlab-ci.yml`, `.github/workflows/ci.yml` | пайплайны: сборка → развёртывание → тесты → отчёты → уборка |

## Требования

- Linux с Docker и compose v2 (WSL2 тоже подходит);
- модуль ядра `tun` и доступ к `/dev/net/tun` — без него UPF и UE не поднимут туннель;
- около 2,5 ГБ свободной памяти и 6 ГБ диска.

Установка Docker: `sudo ./scripts/setup-docker.sh` (с ключом `MIRROR=1`, если Docker Hub
недоступен напрямую).

## Запуск

```bash
./scripts/up.sh          # собрать, поднять, завести абонента, дождаться регистрации
./scripts/test.sh        # прогнать автотесты, отчёты в reports/
./scripts/logs.sh amf 100
./scripts/down.sh        # погасить (--purge — вместе с базой)
```

Проверить руками, что абонент в сети:

```bash
docker exec o5g-ue nr-cli imsi-999700000000001 -e status
docker exec o5g-ue ping -I uesimtun0 -c 3 10.45.0.1
```

## Тесты

16 проверок, разбитых по маркерам — прогонять можно выборочно:

```bash
./scripts/test.sh -m infra          # стенд поднялся, NF зарегистрированы в NRF
./scripts/test.sh -m subscriber     # профиль абонента в базе
./scripts/test.sh -m registration   # регистрация, сессия, пользовательский трафик
./scripts/test.sh -m negative       # неизвестный абонент и неверный ключ SIM
```

Что именно проверяется и какому требованию соответствует — в [docs/test-plan.md](docs/test-plan.md).

Ключевые проверки, не сводящиеся к «код ответа 200»:

- сигнальный обмен идёт по **HTTP/2** — версия протокола проверяется явно;
- адрес абоненту выдан **из пула, заданного в конфиге SMF**, а не любой;
- трафик реально **проходит через UPF** (ping через `uesimtun0`);
- факт регистрации есть **в журнале AMF**, а не только в ответе устройства;
- после неудачных попыток чужих абонентов **легальный остаётся в сети**, а функции не падают.

## Известные ограничения

- Радиоинтерфейс эмулируется: дефекты физического уровня и роуминга здесь не ловятся.
- Пайплайн рассчитан на раннер с доступом к docker-сокету и `/dev/net/tun`.
- Первая сборка образов занимает 10–15 минут (компиляция UERANSIM), дальше кешируется.

## Если сборка образов недоступна

Скопируйте `.env.example` в `.env` и раскомментируйте готовые образы — стенд поднимется
на них без локальной сборки:

```
IMAGE_OPEN5GS=gradiant/open5gs:2.7.2
IMAGE_UERANSIM=gradiant/ueransim:3.2.6
```
